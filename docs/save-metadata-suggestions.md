# 保存情報候補

## 対象

- APIが取得済みHTMLの`title`を正規化し、任意のページタイトルとして返す。
- FrontendがページタイトルとURLから作品名、話タイトル、話数をルールベースで推定する。
- IndexedDB内の作品・話を参照し、既存作品候補を順位付けする。
- 推定結果は編集可能な初期値または候補として表示し、自動保存しない。

## 現行フロー

1. `PageAnalyzer`がHTMLを取得し、画像候補だけをAPIレスポンスへ渡す。
2. `pageImageAnalyzer.ts`が候補をFrontendの解析成功状態へ変換する。
3. `SaveView.vue`が解析後の掲載元URLだけを3登録モードへ反映する。
4. 作品名、話タイトル、追加先作品はユーザーがすべて手入力・選択する。
5. `episodeNumber`はデータモデルに存在するが、登録入力から保存されていない。

## 変更対象

- API：ページタイトル抽出、ページ解析結果、Pydanticレスポンス
- Frontend契約：Valibotレスポンス、ページ解析状態
- 推定ロジック：タイトル・話数候補、既存作品候補
- 保存UI：候補表示と明示採用、3登録モードの入力
- 登録処理：任意の話数をIndexedDBへ保存

## 方針

- HTML本文、ページタイトル、URLをログへ追加しない。
- ページタイトルは空白を正規化し、200文字を上限とする。
- 年、日付、画像番号など曖昧な数値を話数として採用しない。
- 既存作品はタイトル完全一致を最優先し、同一ホスト・URLパスを補助根拠とする。
- 弱い部分一致だけで追加先作品を自動選択しない。
- ユーザーが編集した値を、モード切り替えや再試行で上書きしない。

- Frontend：`format`、`lint`、`type-check`、`test:unit`が成功（47 files / 287 tests passed）

- 既存作品候補：タイトル完全一致、同一ホストと共通パス、候補なし、複数候補の順位を確認

- 既存テスト一式により、URL重複警告、保存失敗後の再試行、続けて保存を含む保存フローの回帰がないことを確認

### 実サイト確認

`https://commons.wikimedia.org/wiki/Category:Manga`を解析し、次を確認した。

- ページタイトル`Category:Manga - Wikimedia Commons`をAPIから取得できる
- 作品名と話タイトルの候補`Category:Manga`が表示される
- 新規作品の入力欄へ候補が初期反映され、任意に編集できる
- 登録モードを切り替えて戻っても、ユーザーが編集した作品名が保持される
- ブラウザーコンソールにエラーがない

画像プロキシでは既存の`Content-Length`不整合による上流取得エラーを確認した。候補機能の変更範囲外であり、画像単位の失敗表示によって画面操作を継続できる。
